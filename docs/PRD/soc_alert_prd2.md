# 分诊子 Agent 设计 PRD

## 1. 文档信息
- 产品名称：安全告警分诊子 Agent
- 文档版本：v1.0
- 文档类型：产品需求文档（PRD）
- 目标读者：产品、运营、安全分析团队、平台工程团队

## 2. 背景与目标
在安全运营场景中，告警来源多、结构不统一、上下文缺失严重，导致人工分诊成本高、结论一致性差、响应时效不稳定。本产品旨在提供一个标准化分诊子 Agent，完成从告警理解、调查规划、证据采集到分诊结论输出的完整闭环。

核心目标：
- 将多源告警转化为结构化分析对象，降低人工解读负担。
- 形成可复用的调查框架与问题清单，提升调查一致性。
- 通过自动化工具采证，减少“人工查询-复制-粘贴”流程。
- 生成可审计、可解释、可落地的分诊结论与处置建议。

非目标：
- 不替代完整事件响应编排平台。
- 不直接执行高风险处置动作（如隔离、封禁、删除）。
- 不做厂商绑定的能力设计。

## 3. 目标用户与使用场景
- 一线 SOC 分析师：处理高频告警、快速判断优先级与真伪倾向。
- 二线应急分析师：针对复杂告警补充证据链和攻击路径判断。
- 安全运营负责人：关注分诊质量、效率和可审计性指标。

典型场景：
- SIEM 规则触发后的首轮分诊。
- EDR 高危行为告警的真伪判断。
- 网络/身份/邮件类告警的跨域关联分析。
- 批量同类告警的标准化调查与分级输出。

## 4. 产品设计原则
- 证据优先：结论必须由可追溯证据支撑。
- 分层推进：先理解告警，再规划调查，再执行采证，最后裁决。
- 不确定性显式化：缺失数据、冲突证据、工具失败必须体现在结论中。
- 人机协同：关键缺参和权限问题允许人工补充与审批。
- 厂商无关：能力按领域抽象，不绑定具体平台。

## 5. 功能架构（产品视角）
### 5.1 能力分层
- 告警理解层：从原始告警提取实体、事件、行为、攻击面和初步战术映射。
- 调查规划层：将理解结果转化为调查维度与调查动作。
- 执行编排层：把调查动作拆解为可执行子问题，并匹配可用工具能力。
- 证据执行层：调用工具完成采证，沉淀成功/失败/跳过状态。
- 裁决输出层：汇总证据形成分诊结论、优先级、置信度和建议。
- 观测审计层：记录过程日志、关键决策、失败原因与结果摘要。

### 5.2 结果对象
- 分诊结果对象：包含分类、严重度、优先级、真伪评估、攻击映射、结论文本。
- 执行结果对象：包含每个子问题的执行状态、工具回传、错误原因、统计摘要。
- 过程上下文对象：包含调查框架、任务拆解、证据引用关系。

## 6. 端到端执行流程
### 阶段 A：告警标准化理解
输入原始告警（允许结构化或半结构化），输出统一的理解结果：
- 告警概要（类型、时间、严重度等）。
- 核心实体（资产、账户、进程、文件、网络标识等）。
- 关键行为与事件链片段。
- 攻击面分类与通用战术映射。
- 相关领域知识注记（常见误报来源、常见攻击模式）。

要求：
- 不在本阶段直接给出恶意/良性裁决。
- 缺失字段使用“未知”或空结构表达，不允许臆断补全。

### 阶段 B：调查框架设计
基于阶段 A 输出，构建 3-6 个调查维度，并生成调查动作清单：
- 每个调查动作需明确目的、所需证据类型、归属调查维度。
- 动作数量根据复杂度动态扩展，覆盖主要攻击面与关键战术路径。

要求：
- 输出应可复用、可追踪、可扩展。
- 本阶段不下最终结论，不给处置判定。

### 阶段 C：可执行问题拆解
将调查动作拆成可验证、可查询、可采证的子问题：
- 每个子问题必须具备唯一标识和明确检验目标。
- 能自动执行的子问题必须绑定对应工具能力。
- 无法自动执行的子问题需标记原因，并保留后续人工调查入口。

要求：
- 子问题需具备机器可解析结构。
- 参数必须严格来源于能力定义，禁止自由改写字段语义。

### 阶段 D：自动化证据采集与执行
执行器按子问题批量调用工具并汇总结果：
- 对可执行子问题进行并发采证。
- 对缺参、授权缺失、能力不匹配等情况进行失败归因。
- 对不可执行子问题进行跳过归档，并保留动作理由。

执行状态：
- 成功：返回有效证据结果。
- 失败：返回错误原因和失败上下文。
- 跳过：标记不执行原因，不影响流程闭环。

### 阶段 E：分诊裁决输出
将“理解结果 + 规划结果 + 拆解结果 + 执行结果”统一汇总，输出最终分诊结果：
- 告警分类、严重度、优先级。
- 真伪倾向及置信度。
- 攻击战术/技术映射。
- 结论与后续建议（即时、短期、长期）。

要求：
- 结论必须引用证据与失败信号。
- 证据不足时必须明确不确定性来源。

## 7. 工具集构造需求（厂商无关）
### 7.1 能力域抽象
工具集应按能力域组织，而非按厂商组织：
- SIEM 查询域：日志检索、关联检索、时间窗口追踪。
- EDR 调查域：终端行为、进程链、文件信誉、告警上下文。
- 网络/NDR 域：流量上下文、会话关联、可疑通信特征。
- 威胁情报域：IOC 信誉、历史命中、外部情报关联。
- 资产与身份域：资产关键度、身份风险、权限异常背景。

### 7.2 工具接入原则
- 统一输入输出契约：对外保持稳定参数语义与结果结构。
- 能力路由与适配：根据子问题类型和上下文自动路由到合适能力域。
- 最小必要调用：仅在可降低不确定性时触发工具，避免无效扩查。
- 可回溯执行：每次调用必须记录“为什么调用、调用了什么、得到什么”。

### 7.3 授权与权限模型
- 支持会话级临时授权与用户级持久授权。
- 缺失授权时触发人工补充流程，允许选择是否长期保存凭据。
- 授权信息需最小暴露、全链路脱敏、具备生命周期清理策略。

### 7.4 失败降级与容错
- 工具不可用不应阻断整体分诊流程。
- 必须输出“证据缺口说明”和“可替代调查方向”。
- 对外部依赖失败进行可观测分类（超时、认证失败、参数缺失、返回异常）。

## 8. 当前能力结论（现状分析提炼）
基于现有分诊子 Agent 运行设计，可抽象得到以下已落地能力：
- 已形成“理解-规划-拆解-执行-裁决”的标准化五段式闭环。
- 已具备机器可解析的中间结果协议，支持自动执行阶段接力。
- 已具备批量执行器，可统一处理成功/失败/跳过并输出统计摘要。
- 已具备跨能力域的调查支持，覆盖日志、终端、网络与情报增强场景。
- 已具备人工介入机制，可在关键信息缺失时恢复执行链路。
- 已具备过程日志与执行留痕，支持复盘与审计。

## 9. 输出结果定义
分诊子 Agent 最终应提供以下结果：
- 分诊结论：分类、严重度、优先级、真伪倾向、置信度。
- 证据摘要：核心证据条目、证据来源、证据与结论映射关系。
- 不确定性说明：缺失字段、冲突证据、执行失败影响范围。
- 行动建议：分层次建议（即时、短期、长期）与升级触发条件。

## 10. 关键指标（KPI）
- 分诊时效：单告警端到端平均耗时。
- 自动化覆盖率：无需人工介入即可完成分诊的比例。
- 结论可解释率：包含可追溯证据引用的结果占比。
- 误报识别有效率：后验验证为良性事件的准确识别率。
- 升级命中率：高优先级升级后被证实为有效事件的比例。
- 工具可用性：工具调用成功率与平均恢复时间。

## 11. 里程碑建议
- M1（标准化）：统一输入输出协议与五段式流程模板。
- M2（自动化）：完善能力路由、批量执行、失败归因与审计记录。
- M3（质量提升）：引入置信度校准、跨域证据融合、批量同类告警优化。
- M4（运营化）：建立质量看板、告警分层策略、持续调优机制。

## 12. 风险与约束
- 数据质量风险：原始告警字段缺失或格式混乱影响结论稳定性。
- 外部依赖风险：工具能力波动导致证据链不完整。
- 权限合规风险：授权采集、存储与审计流程需要严格治理。
- 解释性风险：复杂场景下结论需避免“高置信但低证据”。

## 13. 验收标准
- 能稳定产出完整分诊结果结构，不因单点工具失败而中断。
- 任意结论可追溯到对应证据或缺口说明。
- 支持 SIEM、EDR、网络与情报四类能力域最小闭环。
- 人工介入后可恢复流程并完成结果输出。
- 可提供流程级与子问题级执行留痕，满足复盘要求。
