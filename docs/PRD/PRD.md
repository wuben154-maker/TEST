## 1. 产品概述

### 1.1 产品定位

SecManus Workspace 是一个面向一线安全工程师的 AI 驱动自动化安全分析平台，旨在通过智能 Agent 系统自动化处理各类安全分析任务，提升安全运营效率，减少重复性工作，并支持深度安全研究和调查。

### 1.2 核心价值主张

- **自动化处理**：将安全工程师从重复性、低价值的分析任务中解放出来
- **智能决策**：基于 AI 的意图识别和上下文关联，自动规划、决策和执行
- **深度分析**：支持多维度安全知识搜索和深度研究
- **一体化平台**：统一承载多种安全分析场景，避免工具碎片化
- **可解释性**：提供完整的推理过程和决策链路，确保分析结果可追溯

### 1.3 产品愿景

成为安全工程师的超级智能伙伴，让安全分析工作更高效、更准确、更智能。

## 2. 目标用户

### 2.1 主要用户群体

#### 2.1.1 一线安全工程师 (SOC Analyst)
- **工作场景**：日常安全告警分析、事件响应、威胁调查
- **核心痛点**：
  - 告警数量庞大，人工分析效率低
  - 需要频繁切换多个工具和平台
  - 缺乏统一的知识库和上下文关联
- **使用需求**：快速分析告警、提取 IOC、关联威胁情报、生成调查报告

#### 2.1.2 安全研究员 (Security Researcher)
- **工作场景**：漏洞研究、恶意软件分析、威胁情报挖掘
- **核心痛点**：
  - 需要深度搜索和关联多个信息源
  - 研究过程缺乏系统化记录
  - 难以快速验证和交叉引用信息
- **使用需求**：深度研究、知识搜索、二进制分析、漏洞情报查询

#### 2.1.3 事件响应工程师 (Incident Responder)
- **工作场景**：安全事件调查、溯源分析、应急响应
- **核心痛点**：
  - 需要快速整合多源数据
  - 调查过程缺乏结构化记录
  - 难以快速生成标准化报告
- **使用需求**：自动化溯源、日志分析、IOC 提取、报告生成

#### 2.1.4 安全运营团队 (Security Operations Team)
- **工作场景**：日常安全运营、威胁监控、安全评估
- **核心痛点**：
  - 需要处理大量邮件、文件、日志
  - 缺乏统一的协作平台
  - 知识沉淀和共享困难
- **使用需求**：批量分析、知识共享、协作记录、报告导出

### 2.2 用户画像

**典型用户：张工（SOC 分析师）**
- 年龄：28-35 岁
- 工作经验：3-8 年安全分析经验
- 技术背景：熟悉常见安全工具（SIEM、EDR、威胁情报平台）
- 工作习惯：每天处理 50-100 个安全告警，需要快速判断和响应
- 核心诉求：提升分析效率，减少误报，快速生成报告

## 4. 功能详细说明

### 4.1 智能意图识别与上下文关联 (Intent Understanding & Context)

#### 4.1.1 功能描述
理解用户的自然语言输入，识别分析意图，关联历史上下文，提供智能化的分析建议。

#### 4.1.2 核心能力
- **意图识别**：识别用户的分析意图（邮件分析、二进制分析、告警分析等）
- **上下文理解**：理解对话历史和项目上下文
- **技能选择**：根据意图自动选择合适的安全技能
- **参数提取**：从用户输入中提取分析所需的参数
- **多轮对话**：支持多轮交互，根据用户反馈调整分析策略

#### 4.1.3 使用场景
- 用户输入自然语言，系统自动识别意图并执行分析
- 在对话中引用之前的分析结果
- 根据上下文自动补全分析参数
- 提供分析建议和下一步操作

#### 4.1.4 功能要求
- **FR-IUC-001**: 支持自然语言输入，识别分析意图（准确率 > 90%）
- **FR-IUC-002**: 自动关联项目历史对话和上下文
- **FR-IUC-003**: 根据意图自动选择合适的安全技能模块
- **FR-IUC-004**: 从用户输入中提取分析参数（文件、URL、IP、文本等）
- **FR-IUC-005**: 支持多轮对话，记住之前的分析结果和用户偏好
- **FR-IUC-006**: 提供分析建议，引导用户完成分析任务
- **FR-IUC-007**: 支持模糊意图处理，通过提问澄清用户需求

#### 4.1.5 技术实现
- 使用 `intent_understanding` 中间件
- 实现基于 LLM 的意图识别模型
- 使用向量数据库存储和检索上下文
- 实现对话状态管理

### 4.2 规划、决策与执行 (Planning, Decision & Execution)

#### 4.2.1 功能描述
基于分析任务，自动制定分析计划，做出决策，执行分析步骤，并根据结果调整策略。

#### 4.2.2 核心能力
- **任务规划**：将复杂任务拆解为子任务，制定执行计划
- **智能决策**：根据分析结果和上下文，做出下一步决策
- **自动执行**：自动执行分析步骤，调用相应的工具和技能
- **结果评估**：评估分析结果的完整性和准确性
- **策略调整**：根据中间结果调整分析策略

#### 4.2.3 使用场景
- 复杂的安全分析任务，需要多步骤执行
- 根据初步分析结果，决定下一步分析方向
- 自动执行分析工作流，减少人工干预
- 动态调整分析策略，优化分析效率

#### 4.2.4 功能要求
- **FR-PDE-001**: 自动将复杂任务拆解为可执行的子任务
- **FR-PDE-002**: 制定分析计划，包含任务顺序、依赖关系、预期结果
- **FR-PDE-003**: 根据分析结果和上下文，自动做出决策
- **FR-PDE-004**: 自动执行分析步骤，调用相应的工具和技能
- **FR-PDE-005**: 评估分析结果的完整性和准确性
- **FR-PDE-006**: 根据中间结果动态调整分析策略
- **FR-PDE-007**: 提供分析过程的完整记录和可解释性
- **FR-PDE-008**: 支持用户干预和手动调整分析计划

#### 4.2.5 技术实现
- 使用 LangGraph 实现任务编排
- 实现任务规划器（Task Planner）
- 使用决策树或规则引擎进行决策
- 实现工作流执行引擎

### 4.3 通用深度研究 (Deep Research)

#### 4.3.1 功能描述
支持用户对任意主题进行深度研究，通过多源信息收集、分析和综合，生成结构化的研究报告。

#### 4.3.2 核心能力
- **多源信息收集**：支持 Web 搜索、文档抓取、知识库查询
- **信息综合与分析**：自动整理、去重、关联多源信息
- **结构化报告生成**：生成包含摘要、详细发现、引用来源的研究报告
- **研究计划制定**：自动拆解研究主题，制定研究计划

#### 4.3.3 使用场景
- 研究某个安全漏洞的详细信息
- 调查某个威胁组织的活动历史
- 分析某个安全技术的原理和应用
- 研究某个安全事件的影响范围

#### 4.3.4 功能要求
- **FR-DR-001**: 支持自然语言输入研究主题
- **FR-DR-002**: 自动生成研究计划，包含关键问题和搜索策略
- **FR-DR-003**: 支持多轮交互式研究，根据初步发现深化研究
- **FR-DR-004**: 生成的研究报告包含执行摘要、详细发现、引用来源
- **FR-DR-005**: 支持导出研究报告为 Markdown、PDF、DOCX 格式

#### 4.3.5 技术实现
- 使用 `deep-research` 技能模块
- 集成 Web 搜索工具（Firecrawl、Google Search API）
- 使用 LLM 进行信息综合和报告生成

### 4.4 安全知识深度搜索 (Security Knowledge Search)

#### 4.4.1 功能描述
针对安全领域的专业知识进行深度搜索，包括漏洞信息、威胁情报、安全技术、攻击手法等。

#### 4.4.2 核心能力
- **漏洞知识搜索**：CVE 信息、漏洞详情、利用方式、补丁信息
- **威胁情报搜索**：威胁组织、攻击活动、IOC、TTP（战术、技术、程序）
- **安全技术搜索**：安全工具、检测规则、防护技术、最佳实践
- **知识关联**：自动关联相关的漏洞、威胁、技术信息

#### 4.4.3 使用场景
- 查询某个 CVE 的详细信息、影响范围和利用方式
- 搜索某个威胁组织的攻击手法和 IOC
- 查找某个安全技术的实现方法和工具
- 关联分析多个安全事件和威胁指标

#### 4.4.4 功能要求
- **FR-SKS-001**: 支持按 CVE ID、威胁组织、攻击技术等维度搜索
- **FR-SKS-002**: 集成多个威胁情报源（VirusTotal、AlienVault OTX、MITRE ATT&CK 等）
- **FR-SKS-003**: 支持知识图谱式关联，展示相关漏洞、威胁、技术的关系
- **FR-SKS-004**: 提供搜索结果的置信度评分和来源可信度
- **FR-SKS-005**: 支持保存常用搜索和创建知识库

#### 4.4.5 技术实现
- 集成威胁情报 API（VirusTotal、OTX、AbuseIPDB 等）
- 使用向量数据库存储和检索安全知识
- 实现知识图谱构建和关联分析

### 4.5 邮件自动化安全分析 (Email Security Analysis)

#### 4.4.1 功能描述
自动分析二进制文件（PE、ELF、Mach-O），检测恶意软件特征、加壳、混淆等。

#### 4.4.2 核心能力
- **文件格式识别**：识别 PE、ELF、Mach-O 等文件格式
- **静态分析**：分析文件头、导入表、导出表、字符串
- **加壳检测**：检测常见加壳工具（UPX、Themida、VMProtect 等）
- **恶意行为识别**：识别可疑 API 调用、反调试技术、网络行为
- **威胁情报关联**：通过文件哈希查询威胁情报

#### 4.4.3 使用场景
- 分析可疑可执行文件，判断是否为恶意软件
- 检测文件是否加壳或混淆
- 提取文件的 IOC（哈希、字符串、网络连接）
- 关联威胁情报，识别恶意软件家族

#### 4.4.4 功能要求
- **FR-BFA-001**: 支持常见二进制格式（PE32/PE64、ELF、Mach-O）
- **FR-BFA-002**: 自动计算文件哈希（MD5、SHA1、SHA256）
- **FR-BFA-003**: 解析文件头结构，提取元数据（编译时间、入口点、节信息）
- **FR-BFA-004**: 检测常见加壳工具和混淆技术
- **FR-BFA-005**: 提取文件中的字符串、URL、IP 地址
- **FR-BFA-006**: 分析导入表，识别可疑 API 调用
- **FR-BFA-007**: 通过文件哈希查询 VirusTotal 等威胁情报源
- **FR-BFA-008**: 生成二进制分析报告，包含威胁等级和恶意行为预测

#### 4.4.5 技术实现
- 使用 `binary-analysis` 技能模块
- 集成二进制分析库（pefile、pyelftools、lief）
- 实现熵值计算和加壳检测算法
- 集成 VirusTotal API 进行威胁情报查询

### 4.6 二进制文件自动化分析 (Binary File Analysis)

#### 4.5.1 功能描述
自动分析 Webshell 文件，检测后门特征、识别 Webshell 类型、提取攻击载荷。

#### 4.5.2 核心能力
- **Webshell 检测**：识别常见 Webshell 特征和签名
- **代码分析**：分析 Webshell 代码逻辑和功能
- **类型识别**：识别 Webshell 类型（PHP、ASP、JSP、Python 等）
- **功能提取**：提取 Webshell 的功能（文件管理、命令执行、数据库操作等）
- **混淆检测**：检测代码混淆和编码技术

#### 4.5.3 使用场景
- 检测上传的 Web 文件是否为 Webshell
- 分析已发现的 Webshell，了解其功能
- 提取 Webshell 中的攻击载荷和 IOC
- 批量扫描 Web 目录，检测 Webshell

#### 4.5.4 功能要求
- **FR-WSA-001**: 支持常见 Web 脚本格式（PHP、ASP、JSP、Python、Node.js）
- **FR-WSA-002**: 检测常见 Webshell 特征（eval、exec、system、shell_exec 等危险函数）
- **FR-WSA-003**: 识别 Webshell 类型和家族（中国菜刀、冰蝎、蚁剑等）
- **FR-WSA-004**: 分析 Webshell 功能（文件操作、命令执行、数据库操作、反弹 Shell）
- **FR-WSA-005**: 检测代码混淆和编码（Base64、Gzip、自定义加密）
- **FR-WSA-006**: 提取 Webshell 中的 IOC（IP、域名、密码、后门路径）
- **FR-WSA-007**: 生成 Webshell 分析报告，包含威胁等级和清除建议

#### 4.5.5 技术实现
- 创建 `webshell-analysis` 技能模块
- 实现 Webshell 特征检测规则库
- 使用静态代码分析技术
- 集成 Webshell 签名库（NeoPI、Webshell-Scanner）

### 4.10 多智能体架构 (Multi-Agent Architecture)

#### 4.10.1 功能描述
采用多智能体架构，将各个专业安全分析任务分配给专门的子智能体（Sub-Agent）来实现，每个子智能体专注于特定的安全领域，通过 Skill 机制实现能力的模块化和可扩展性。

#### 4.10.2 核心能力
- **主智能体（Master Agent）**：负责意图识别、任务规划、子智能体调度和结果汇总
- **子智能体（Sub-Agents）**：专门处理特定领域的安全分析任务
  - **安全分析智能体（Security Agent）**：处理邮件、二进制、Webshell 等安全分析任务
  - **研究智能体（Research Agent）**：处理深度研究和知识搜索任务
  - **溯源智能体（Investigation Agent）**：处理自动化溯源调查任务
  - **告警分析智能体（Alert Analysis Agent）**：处理 SIEM 告警和日志分析任务
- **Skill 机制**：每个子智能体通过 Skill 模块实现具体功能，支持动态加载和扩展
- **智能体协作**：支持多个子智能体并行工作，协同完成复杂任务
- **结果聚合**：自动汇总多个子智能体的分析结果，生成综合报告

#### 4.10.3 使用场景
- 复杂安全分析任务需要多个专业领域协同处理
- 需要并行执行多个分析任务以提升效率
- 需要根据任务类型自动选择合适的专业智能体
- 需要扩展新的安全分析能力时，通过添加新的 Skill 实现

#### 4.10.4 功能要求
- **FR-MAA-001**: 实现主智能体（Master Agent），负责任务分发和协调
- **FR-MAA-002**: 实现安全分析子智能体（Security Sub-Agent），处理邮件、二进制、Webshell 分析
- **FR-MAA-003**: 实现研究子智能体（Research Sub-Agent），处理深度研究和知识搜索
- **FR-MAA-004**: 实现溯源子智能体（Investigation Sub-Agent），处理自动化溯源调查
- **FR-MAA-005**: 实现告警分析子智能体（Alert Analysis Sub-Agent），处理 SIEM 告警和日志分析
- **FR-MAA-006**: 实现 Skill 机制，支持动态加载和管理安全分析技能模块
- **FR-MAA-007**: 支持子智能体并行执行，提升分析效率
- **FR-MAA-008**: 实现智能体间的通信和协作机制
- **FR-MAA-009**: 自动汇总多个子智能体的分析结果，生成综合报告
- **FR-MAA-010**: 支持自定义子智能体和 Skill，便于扩展新功能

#### 4.10.5 技术实现
- 使用 LangGraph 实现多智能体编排和任务流管理
- 实现主智能体（Master Agent）作为任务调度中心
- 为每个专业领域实现专门的子智能体（Sub-Agent）
- 通过 Skill 模块化架构实现功能解耦和扩展
  - 每个 Skill 包含：技能描述（SKILL.md）、工具脚本（scripts/）、配置参数
  - 支持 Skill 的动态加载、注册和调用
- 使用消息队列或事件总线实现智能体间通信
- 实现结果聚合器，汇总多个智能体的输出
- 使用向量数据库存储 Skill 元数据和能力描述

#### 4.10.6 Skill 架构设计

**Skill 目录结构**：
```
skills/
├── email-security/          # 邮件安全分析 Skill
│   ├── SKILL.md            # 技能描述和触发词
│   └── scripts/            # 工具脚本
├── binary-analysis/         # 二进制分析 Skill
│   ├── SKILL.md
│   └── scripts/
├── webshell-analysis/       # Webshell 分析 Skill
│   ├── SKILL.md
│   └── scripts/
├── soc-alert/              # 告警分析 Skill
│   ├── SKILL.md
│   └── scripts/
└── deep-research/          # 深度研究 Skill
    ├── SKILL.md
    └── scripts/
```

**Skill 元数据格式**：
- `name`: Skill 唯一标识
- `display_name`: 显示名称
- `description`: 功能描述
- `triggers`: 触发词列表（用于意图识别）
- `tags`: 标签分类
- `priority`: 优先级
- `version`: 版本号
- `workflow_steps`: 工作流步骤定义

**Skill 与子智能体的关系**：
- 每个子智能体可以调用多个相关的 Skill
- 主智能体根据意图识别结果，选择合适的子智能体和 Skill
- Skill 是功能的最小单元，子智能体是任务的执行单元
