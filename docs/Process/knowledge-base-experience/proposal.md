# Proposal — 知识库「知识感」体验

## Problem

`/knowledge` 当前以窄表格为主，缺少检索、汇总与空状态引导，用户容易将其感知为「文件下载列表」而非「可回忆、可复用的归档知识」。

## Goals

- 页面顶部提供**可读汇总**（条数、总大小、最近更新时间）。
- 支持**按名称即时搜索**（前端过滤，无新 API）。
- 列表改为**卡片式信息层次**：类型图标、标题、元信息行、与「打开工作区」「下载」分离的操作。
- **空状态**说明来源并引导前往工作台。
- **刷新**与**高亮行**（`?highlight=`）视觉加强；下载成功给予轻量反馈。

## Non-goals

- 后端新字段、全文检索、AI 摘要、批量下载、文件上传入口。
- 改动自动归档 pipeline（`knowledgeArchive.ts`）行为。

## Users

已登录、使用专业安全/研究分析并触发 Word 归档的用户。

## Success metrics

- 用户在 10 条以上文档时仍能通过搜索在 3 次击键内缩小列表（主观可用性）。
- 从对话「在知识库中查看」链入时，高亮条目在视口内可辨识。

## Dependencies

- 现有 `GET /knowledge` 与 `KnowledgeItem` 字段不变。
