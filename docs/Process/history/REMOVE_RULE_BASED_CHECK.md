# 移除基于规则的输入检查

## 变更说明

根据要求，**严禁在代码中使用规则来判断用户的输入**。意图理解的判断超出产品能力范围只能通过主系统提示词（`MASTER_AGENT.md`）来进行边界定义。

## 已移除的内容

### 1. 关键词列表（硬编码规则）

**移除位置**：`app/middleware/intent_classifier.py` 第255-275行

**移除内容**：
- `self._security_keywords` - 安全相关关键词列表
- `self._unrelated_keywords` - 无关输入关键词列表

**原因**：这些硬编码的规则违反了"严禁在代码中使用规则来判断用户的输入"的要求。

---

### 2. 输入相关性检查调用

**移除位置**：`app/middleware/intent_classifier.py` 第297-313行

**移除内容**：
```python
# P0 Enhancement: Input relevance check
relevance_check = self._check_input_relevance(text, language)
if not relevance_check["is_relevant"]:
    # ... 返回低置信度结果
```

**原因**：这是基于规则的检查，应该由LLM根据提示词来判断。

---

### 3. Fallback中的规则匹配逻辑

**移除位置**：`app/middleware/intent_classifier.py` `_get_fallback_result()` 方法

**移除内容**：
- 基于关键词的任务分类逻辑
- 根据关键词匹配确定 `task_category` 和 `skill_hint` 的代码

**原因**：Fallback不应该使用规则匹配，应该返回通用的低置信度结果。

---

## 保留的内容

### 1. 提示词中的能力边界定义

**位置**：`app/prompts/MASTER_AGENT.md` 第42-66行

**内容**：
- **What This System Can Do**: 明确列出系统能力
- **What This System CANNOT Do**: 明确列出系统限制
- **Out of Scope Detection Rules**: 详细指导LLM如何识别超出范围的请求

**增强内容**：
- 更详细的超出范围检测规则
- 明确要求LLM在识别超出范围请求时设置 `confidence=0.1` 和 `task_category="unknown"`
- 提供清晰的错误消息格式

---

## 实现方式

### LLM驱动的边界检测

现在所有的边界检测都通过LLM根据提示词来判断：

1. **LLM读取提示词**：
   - 从 `MASTER_AGENT.md` 加载能力边界定义
   - 理解系统能做什么和不能做什么

2. **LLM判断输入**：
   - 根据提示词中的规则判断输入是否超出范围
   - 如果超出范围，设置 `confidence=0.1` 和 `task_category="unknown"`

3. **LLM生成响应**：
   - 对于超出范围的请求，生成友好的错误消息
   - 说明系统的能力边界

---

## 优势

### 1. 灵活性
- ✅ 无需修改代码即可调整能力边界
- ✅ 可以通过更新提示词来扩展或收缩能力范围
- ✅ 支持更复杂的判断逻辑（LLM的语义理解能力）

### 2. 一致性
- ✅ 所有判断都通过LLM，保持一致性
- ✅ 避免规则和LLM判断不一致的问题

### 3. 可维护性
- ✅ 能力边界定义集中在提示词中
- ✅ 易于理解和修改

---

## 注意事项

### 1. LLM必须正确理解提示词

**要求**：
- 提示词必须清晰明确
- 提供足够的示例和指导
- 明确超出范围的判断标准

**验证**：
- 测试各种超出范围的输入
- 确保LLM能够正确识别并返回低置信度结果

### 2. Fallback处理

**当前实现**：
- LLM失败时，返回通用的低置信度结果（`confidence=0.2`）
- 不进行任何规则匹配
- 让用户知道服务暂时不可用

**原因**：
- 避免在LLM不可用时使用规则判断
- 保持系统行为的一致性

### 3. 性能考虑

**影响**：
- 所有输入都需要通过LLM判断
- 可能增加延迟（但通常可接受）

**优化**：
- LLM判断通常很快（<1秒）
- 如果需要，可以考虑缓存常见请求

## 测试建议

### 1. 超出范围请求测试

**测试用例**：
- "今天天气怎么样？" → 应该返回 `confidence=0.1`, `task_category="unknown"`
- "帮我写一首诗" → 应该返回 `confidence=0.1`, `task_category="unknown"`
- "当前时间是什么？" → 应该返回 `confidence=0.1`, `task_category="unknown"`

**验证点**：
- LLM是否能够正确识别超出范围的请求
- 是否返回低置信度结果
- 错误消息是否友好且清晰

### 2. 边界情况测试

**测试用例**：
- "分析这个邮件" → 应该正常处理（在范围内）
- "帮我分析一下这个安全事件" → 应该正常处理（在范围内）
- "帮我写一个安全分析报告" → 可能需要澄清（边界情况）

**验证点**：
- LLM是否能够正确区分在范围和超出范围的请求
- 边界情况是否得到正确处理
