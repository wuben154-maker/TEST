# 复杂度评估功能用途分析

## 功能概述

复杂度评估（`_assess_complexity`）用于评估用户请求的复杂度（1-10 分），用于决定任务规划的策略。

---

## 主要用途

### 1. **决定是否使用 LLM 进行任务分解**

**核心决策逻辑**：
```python
async def plan_tasks(self, user_input: str, intent_result: Any, language: str) -> TaskPlan:
    # Priority 1: 如果意图理解已有任务列表，直接使用（不评估复杂度）
    intent_tasks = getattr(intent_result, 'tasks', []) or []
    if intent_tasks:
        return self._create_plan_from_intent_tasks(intent_result, language)
    
    # Priority 2: 如果没有任务列表，评估复杂度
    complexity = self._assess_complexity(user_input, intent_result)
    
    # 简单任务（复杂度 <= 3）：直接创建单一任务，不需要 LLM
    if complexity <= self.complexity_threshold:  # 默认 threshold = 3
        return self._create_simple_plan(intent_result, language)
    
    # 复杂任务（复杂度 > 3）：使用 LLM 进行智能任务分解
    plan_result = await self._llm_plan(user_input, intent_result, language, complexity)
```

**决策流程**：
```
意图理解有任务列表？
  ├─ 是 → 直接使用任务列表（不评估复杂度）
  └─ 否 → 评估复杂度
         ├─ 复杂度 <= 3 → 简单计划（单一任务，不需要 LLM）
         └─ 复杂度 > 3  → LLM 规划（智能任务分解）
```

---

### 2. **优化 LLM 调用成本**

**目的**：
- 简单任务不需要 LLM 规划，直接创建单一任务计划
- 只有复杂任务才使用 LLM 进行智能分解
- 减少不必要的 LLM 调用，提高效率

**示例**：
- **简单任务**（复杂度 1-3）：
  - "分析这个文件" → 复杂度 1 → 直接创建单一任务
  - 不需要 LLM 调用
  
- **复杂任务**（复杂度 4-10）：
  - "分析这个文件，然后检查 IP 1.2.3.4，最后生成报告" → 复杂度 7 → 使用 LLM 分解为多个任务

---

### 3. **评估指标**

复杂度评估考虑以下因素：

#### Priority 1: 意图理解结果（优先使用）
- **任务数量**：如果意图理解已生成多个任务，直接返回高复杂度
- **置信度**：低置信度（< 0.5）增加复杂度
- **分析目标数量**：目标越多，复杂度越高
- **关键实体数量**：实体越多，复杂度越高

#### Priority 2: 关键词匹配（补充）
- **多目标指示词**：and, 以及, 还有, 另外, 同时, 并且
- **多动作指示词**：分析, 检查, 扫描, 查询, 调查
- **顺序连接词**：然后, 接着, 之后, first, then, after

#### Priority 3: 输入特征
- **输入长度**：> 500 字符 +1，> 1000 字符 +1
- **文件数量**：多个文件增加复杂度

---

## 当前使用场景

### 场景 1：意图理解已生成任务（最常见）
```
用户输入 → 意图理解 → 生成任务列表 → 直接使用（不评估复杂度）
```
**复杂度评估**：不执行

### 场景 2：意图理解未生成任务（较少见）
```
用户输入 → 意图理解 → 未生成任务 → 评估复杂度 → 决策
  ├─ 复杂度 <= 3 → 简单计划
  └─ 复杂度 > 3  → LLM 规划
```
**复杂度评估**：执行，用于决策

---

## 复杂度阈值

**默认阈值**：`complexity_threshold = 3`

**含义**：
- **复杂度 1-3**：简单任务，直接创建单一任务计划
- **复杂度 4-10**：复杂任务，使用 LLM 进行智能分解

**可配置**：
```python
TaskPlanner(
    llm=llm,
    enable_auto_planning=True,
    complexity_threshold=3,  # 可调整
)
```

## 实际效果

### 优势
1. ✅ **减少 LLM 调用** - 简单任务不需要 LLM
2. ✅ **提高效率** - 快速处理简单请求
3. ✅ **降低成本** - 减少 API 调用次数

### 局限性
1. ⚠️ **现在使用较少** - 因为意图理解通常已生成任务列表
2. ⚠️ **评估可能不准确** - 基于关键词匹配，可能误判

---

## 是否需要保留？

### 保留的理由
1. ✅ **Fallback 机制** - 当意图理解未生成任务时，需要决策
2. ✅ **成本优化** - 避免简单任务使用 LLM
3. ✅ **性能优化** - 快速处理简单请求

### 可以简化的理由
1. ⚠️ **使用频率低** - 意图理解通常已生成任务
2. ⚠️ **评估准确性** - 关键词匹配可能不够准确

### 建议
**保留但优化**：
- ✅ 保留复杂度评估功能
- ✅ 优化评估算法，更多依赖意图理解结果
- ✅ 考虑降低阈值或移除关键词匹配（如果意图理解总是生成任务）

## 优化建议

### 方案 1：简化评估（推荐）
```python
def _assess_complexity(self, user_input: str, intent_result: Any) -> int:
    """评估请求的复杂度 (1-10)。"""
    # 如果意图理解有任务列表，直接返回高复杂度（触发 LLM 规划）
    intent_tasks = getattr(intent_result, 'tasks', []) or []
    if len(intent_tasks) > 1:
        return min(len(intent_tasks) * 2, 10)
    
    # 如果没有任务列表，使用置信度判断
    confidence = getattr(intent_result, 'confidence', 0.8)
    if confidence < 0.5:
        return 5  # 低置信度 = 中等复杂度，使用 LLM
    elif confidence < 0.7:
        return 3  # 中置信度 = 简单任务
    else:
        return 2  # 高置信度 = 简单任务
```

**优势**：
- 更简单，更准确
- 完全依赖意图理解结果
- 移除关键词匹配的复杂性

### 方案 2：移除复杂度评估
如果意图理解总是生成任务列表，可以考虑移除复杂度评估，直接：
- 有任务列表 → 使用任务列表
- 无任务列表 → 使用 LLM 规划（不评估复杂度）

## 总结

### 当前用途
1. ✅ **决策是否使用 LLM** - 简单任务不需要 LLM
2. ✅ **成本优化** - 减少不必要的 LLM 调用
3. ✅ **Fallback 机制** - 处理意图理解未生成任务的情况

### 使用频率
- **低** - 因为意图理解通常已生成任务列表
- **仅在边界情况使用** - 当意图理解未生成任务时

### 建议
- ✅ **保留** - 作为 fallback 机制
- ✅ **简化** - 更多依赖意图理解结果，减少关键词匹配
- ⚠️ **可考虑移除** - 如果意图理解总是生成任务列表
