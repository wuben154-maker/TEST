# PLANNING_PROMPT 用途说明

## 概述

`PLANNING_PROMPT` 是 `TaskPlanner` 类中的一个**类属性**，用于定义 LLM 任务规划的提示词模板。它的主要作用是**指导 LLM 如何根据意图理解结果进行任务规划**。

---

## 核心用途

### 1. **LLM 任务规划的指令模板**

`PLANNING_PROMPT` 是一个字符串模板，包含：
- 任务规划的规则和指南
- 意图理解结果的格式说明
- 任务结构的定义
- 响应格式的规范

### 2. **在 `_llm_plan` 方法中使用**

**调用位置**：`task_planner.py:605-636` - `_llm_plan` 方法

**使用流程**：
```python
async def _llm_plan(self, user_input: str, intent_result: Any, language: str, complexity: int) -> dict:
    # 1. 准备提示词参数
    category = getattr(intent_result, 'task_category', None)
    # ... 其他参数准备 ...
    
    # 2. 格式化提示词（使用 PLANNING_PROMPT 模板）
    prompt = self.PLANNING_PROMPT.format(
        category=category_value,
        confidence=confidence,
        summary=summary,
        intent_description=intent_description,
        goals=goals,
        security_subtype=subtype_value,
        research_topic=research_topic,
        input_type=input_type_value,
        file_count=file_count,
        key_entities=key_entities,
        task_descriptions=task_descriptions,
        user_input=user_input,
        language=language,
    )
    
    # 3. 调用 LLM 生成任务规划
    response = await self.llm.ainvoke([
        SystemMessage(content="..."),
        HumanMessage(content=prompt),
    ])
    
    # 4. 解析 LLM 返回的 JSON 响应
    return json.loads(response.content)
```

## 使用场景

### 场景 1：意图理解未生成任务列表（较少见）

**触发条件**：
- 意图理解没有生成 `tasks` 列表
- 复杂度评估 > `complexity_threshold`（默认 3）
- `enable_auto_planning` 为 `True`

**流程**：
```
意图理解 → 未生成任务 → 评估复杂度 → 复杂度 > 3 → 调用 _llm_plan → 使用 PLANNING_PROMPT → LLM 生成任务规划
```

**PLANNING_PROMPT 的作用**：
- 指导 LLM 根据用户输入和意图理解结果创建 Level 1 任务
- 确保遵循"一个文件一个任务"的原则
- 生成正确的任务类型（security/research）和 skill 映射

---

### 场景 2：意图理解已生成任务列表（最常见）

**触发条件**：
- 意图理解已生成 `tasks` 列表
- 但复杂度评估 > `complexity_threshold`
- 需要 LLM 进行任务优化或依赖关系处理

**流程**：
```
意图理解 → 已生成任务 → 评估复杂度 → 复杂度 > 3 → 调用 _llm_plan → 使用 PLANNING_PROMPT → LLM 优化任务规划
```

**PLANNING_PROMPT 的作用**：
- 指导 LLM 使用意图理解的任务列表（不进一步分解）
- 处理依赖关系（根据 `context_needed` 设置 `depends_on`）
- 优化任务优先级和顺序

## 提示词内容结构

### 1. **意图理解结果部分**
```
## Intent Understanding Results
- Category: {category}
- Confidence: {confidence}
- Summary: {summary}
- Intent Description: {intent_description}
- Analysis Goals: {goals}
- Security Subtype: {security_subtype}
- Research Topic: {research_topic}
- Input Type: {input_type}
- File Count: {file_count}
- Key Entities: {key_entities}
```

**作用**：向 LLM 提供意图理解的完整上下文

---

### 2. **任务列表部分**
```
## Tasks Already Identified by Intent Understanding
{task_descriptions}
```

**作用**：如果意图理解已生成任务，展示给 LLM 参考

---

### 3. **任务粒度规则（Level 1 Tasks）**
```
## Task Granularity Rules (Level 1 Tasks)

**CRITICAL: Use tasks from intent understanding as-is (Level 1 Tasks)**

1. **If intent understanding has identified tasks**:
   - Use them directly, do NOT further decompose
   - Each task is a Level 1 task (e.g., "Analyze email file [filename]")
   - Do NOT create detailed steps - sub-agents will handle that

2. **If intent understanding has NOT identified tasks** (rare):
   - Create Level 1 tasks based on files and text
   - One file = One task
   - Multiple files = Multiple tasks
```

**作用**：
- 明确"一个文件一个任务"的原则
- 禁止进一步分解任务
- 禁止生成详细步骤

---

### 4. **任务类型和技能映射**
```
## Task Types
- **security**: Use for security-specific analysis. Assign a skill_name from the available skills.
- **research**: Use for general information gathering, deep research, or non-security topics.

## Available Security Skills
| Skill | Description | Best For |
|-------|-------------|----------|
| email-security | Email header analysis, phishing detection | Suspicious emails, phishing |
| binary-analysis | Malware analysis, file inspection | Executables, suspicious files |
| ...
```

**作用**：
- 定义任务类型（security/research）
- 提供可用的安全技能列表
- 指导 LLM 选择合适的 skill

---

### 5. **响应格式规范**
```
## Response Format (JSON)
{
  "complexity_score": 1-10,
  "is_single_task": true|false,
  "reasoning": "Brief explanation of why this breakdown was chosen",
  "tasks": [
    {
      "id": "task-1",
      "title": "Concise task title (5-10 words)",
      "description": "What this task will accomplish (Level 1, high-level)",
      "task_type": "security|research",
      "skill_name": "skill-name-or-null",
      "priority": 1,
      "depends_on": []
    }
  ]
}

**IMPORTANT**: Do NOT include "steps" in the response. Steps will be generated by sub-agents during execution.
```

**作用**：
- 定义 LLM 返回的 JSON 格式
- 明确不包含 `steps` 字段（由子智能体生成）
- 要求返回任务依赖关系

---

## 关键规则

### ✅ 必须遵守的规则

1. **使用意图理解的任务列表**：如果意图理解已生成任务，直接使用，不进一步分解
2. **Level 1 任务**：保持任务高级别，不创建详细步骤
3. **一个文件一个任务**：多个文件生成多个任务
4. **依赖关系**：根据 `context_needed` 设置 `depends_on`

### ❌ 禁止事项

1. **不要创建详细步骤**：子智能体会处理
2. **不要进一步分解 Level 1 任务**
3. **不要合并多个文件到一个任务**（除非意图理解明确创建了合并任务）

## 与其他方法的关系

### 1. **`plan_tasks` 方法**
- 主入口方法
- 决定是否调用 `_llm_plan`（使用 PLANNING_PROMPT）
- 如果意图理解已有任务，优先使用 `_create_plan_from_intent_tasks`

### 2. **`_llm_plan` 方法**
- 使用 `PLANNING_PROMPT` 格式化提示词
- 调用 LLM 生成任务规划
- 返回 JSON 格式的任务规划结果

### 3. **`_parse_plan_result` 方法**
- 解析 `_llm_plan` 返回的 JSON
- 转换为 `PlannedTask` 对象
- 处理依赖关系映射

### 4. **`_create_plan_from_intent_tasks` 方法**
- 直接使用意图理解的任务列表（不使用 PLANNING_PROMPT）
- 适用于意图理解已生成任务且复杂度较低的情况

---

## 总结

### PLANNING_PROMPT 的核心作用

1. **指导 LLM 进行任务规划**：提供清晰的规则和格式要求
2. **确保任务粒度正确**：强制执行"一个文件一个任务"和 Level 1 任务原则
3. **处理复杂场景**：当意图理解未生成任务或需要优化时，使用 LLM 进行规划
4. **统一任务格式**：确保所有任务规划遵循相同的结构和规范

### 使用频率

- **低频率**：大多数情况下，意图理解已生成任务，直接使用 `_create_plan_from_intent_tasks`
- **仅在需要时使用**：当复杂度高或意图理解未生成任务时，才使用 `PLANNING_PROMPT` 调用 LLM

### 重要性

虽然使用频率较低，但 `PLANNING_PROMPT` 是系统的**重要后备机制**，确保在边界情况下（意图理解未生成任务）系统仍能正常工作。
